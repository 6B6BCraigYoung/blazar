## b2 · 直接能用、说法一致

对应原则 2（直接能用）、4（一致）、6（对用户负责）。界面变化主要在文字上，截图只拍有变化的地方。

- **错误说人话**（问题 8）：认不出的错误原来直接显示 stderr 第一行，比如 `Error: ENOSPC`、`ECONNRESET`。现在磁盘满、缺程序、连接被重置、没有权限都翻成一句话，中英两套词表一起改。
- **统一用词**（问题 9）：对话外面的“会话”统一叫“对话”，“审批”统一叫“批准”，待处理事项去的地方统一叫“中控台”，不再说一个没有独立页面的“收件箱”。bot 自己的收件箱和线程是另一回事，保留原名。
- **主流程去术语**（问题 10）：新建工作区里的“独立分支”改成“在副本里改：另放一份代码副本、开一个新分支，原目录不受影响”，“主仓正 checkout 着这个分支”改成“原目录正在用这个分支”；开始清单第一步从“运行时”改成“Claude Code 或 Codex”；销毁、冻结副本时说清目录、分支和没提交的改动会怎样；结束后台任务不再提 TERM。
- **派出去的活跟着派活的会话走**（问题 11）：会话用 `send_prompt` 派活又没写权限模式时，沿用自己的模式，不再让用户替别人开的会话逐条点批准；会话用 `create_workspace` 建的工作区默认挂在它所在的工作区名下，列表里折叠在父工作区下面（`standalone: true` 可以不挂）；只读的调度工具（状态、列表、记录、日志、等待）对所有会话自动放行。
- **破坏性操作**（问题 12）：冻结可以随时解冻，不加确认，只把说明写清楚。其余几处（删排队消息、删评审评论、释放认领）影响小，这批没动。

## b6 · 审阅和撤销

对应第二份清单的问题 7、8、9、10、15，原则 6（对用户负责）、1（少即是多）、2（直接能用）、0（好看）。两个子代理先后实现（都要大改差异视图，不能并行），我审完合并。顺带改了 b5 截图意见里的三处。

- **丢弃一个文件或一处改动，能撤销**（问题 7）：差异视图的文件头和每处改动上都有「丢弃」，平时不显示，鼠标悬停或键盘焦点进入时出现。点了立即丢弃，给 5 秒「撤销」。丢弃前 hub 把原内容、可执行位和暂存区那一项存进自己的数据库（不放在仓库里），保留 10 分钟。撤销前先核对文件从丢弃之后有没有再被改过，改过就拒绝，免得盖掉新的改动。只对单个路径操作，从不对整棵树 checkout 或 reset，也不碰提交历史。走的是和提交同一条通道，远程机器上的工作区也能用（只在本机测过）。
- **一个「更改」视图**（问题 8）：原来的「差异」和「Git」两个子页合成一个视图。差异栏只剩五样：「这次的改动 ▾」（比较基准做成下拉）、意见数、显示、⋯、一个主按钮。主按钮按状态切换：有没提交的改动时是「提交…」，有本地提交没推上去时是「推送」，推过还没 PR 时是「创建 PR…」。分支、同步、提交列表、PR 状态放在下面一行，其余操作进 ⋯ 菜单。页头按钮写成「更改 3」，是唯一入口。⋯ 菜单里和页头重复的项删掉了，「检查器」改叫「右侧面板」。⌘⇧G 没有单独的去处了，从默认快捷键里拿掉。
- **主路径上不说 Git 术语**（问题 9）：「相对 HEAD」改成「这次的改动」；「游离 HEAD」改成「没在任何分支上」；「拉取远端」改成「同步到最新」。变基和强制推送只在 ⋯ →「高级」里，各带一句后果说明。推送被拒时问的是「用本地覆盖远端？」。
- **审阅意见存在 hub 里**（问题 10）：行级意见从浏览器的 localStorage 搬到 hub，按工作区保存，换设备或清缓存都不会丢；旧的本地意见第一次打开时搬过去一次。删除意见给 5 秒撤销。
- **这一页对齐令牌**（问题 15）：字号和图标落到 14 / 16 档；6 / 10 的间距换成 4 / 8 / 12；文件头只留底色，文件之间不再是双线；意见框和操作块去掉边框；+N / −N 的红绿只留在汇总处，文件列表和文件头里是灰色。一屏字号从 5 档降到 4 档。
- **b5 截图意见的三处**：「开始」第 1 步里有 CLI 装了但登录失效时，这一步不再打勾，编号圆点变橙色，按钮换成主按钮「重新登录」，点了直接开登录弹窗；工作区里还没跑过任何对话时，托盘写「3 files already changed」，不再像是智能体做的改动；输入框占位文字从「⌘ Esc to focus or unfocus Claude」改成「Ask Claude to…」（Codex 是「Ask Codex to…」），快捷键提示挪进悬停提示。
