## b2 · 直接能用、说法一致

对应原则 2（直接能用）、4（一致）、6（对用户负责）。界面变化主要在文字上，截图只拍有变化的地方。

- **错误说人话**（问题 8）：认不出的错误原来直接显示 stderr 第一行，比如 `Error: ENOSPC`、`ECONNRESET`。现在磁盘满、缺程序、连接被重置、没有权限都翻成一句话，中英两套词表一起改。
- **统一用词**（问题 9）：对话外面的“会话”统一叫“对话”，“审批”统一叫“批准”，待处理事项去的地方统一叫“中控台”，不再说一个没有独立页面的“收件箱”。bot 自己的收件箱和线程是另一回事，保留原名。
- **主流程去术语**（问题 10）：新建工作区里的“独立分支”改成“在副本里改：另放一份代码副本、开一个新分支，原目录不受影响”，“主仓正 checkout 着这个分支”改成“原目录正在用这个分支”；开始清单第一步从“运行时”改成“Claude Code 或 Codex”；销毁、冻结副本时说清目录、分支和没提交的改动会怎样；结束后台任务不再提 TERM。
- **派出去的活跟着派活的会话走**（问题 11）：会话用 `send_prompt` 派活又没写权限模式时，沿用自己的模式，不再让用户替别人开的会话逐条点批准；会话用 `create_workspace` 建的工作区默认挂在它所在的工作区名下，列表里折叠在父工作区下面（`standalone: true` 可以不挂）；只读的调度工具（状态、列表、记录、日志、等待）对所有会话自动放行。
- **破坏性操作**（问题 12）：冻结可以随时解冻，不加确认，只把说明写清楚。其余几处（删排队消息、删评审评论、释放认领）影响小，这批没动。

## b3 · 升级这条路、设置减项、视觉第二轮

对应第 0 条（好看）和原则 1（少即是多）、4（一致）、7（整体体验）。视觉部分按 b1 改后截图的肉眼意见来改。

- **升级**（问题 15）：hub 每 12 小时最多向 GitHub 查一次最新版本，有新版本就在右下角提示一次并给下载链接，「设置 → 数据与关于」里也能看到；桌面端连远程 hub 时，两边版本不一样会提示一次。仓库地址由发布流水线在构建时注入，本地构建从不对外请求；`BLAZAR_NO_UPDATE_CHECK=1` 可以关掉。公证要 Apple Developer ID，还没做。
- **设置减项**（问题 13）：提醒页 9 个按类型的开关收进一张表单，主页面只写“所有事项都提醒”或“关掉了 N 类”；只有一项的“额度分摊”并进“对话与运行”（原来叫“对话与编辑”），设置侧栏从 11 个分区减到 10 个，旧链接 `?s=quota` 自动落到新位置。
- **一个页面一个地址**（问题 14）：`/running`、`/waiting`、`/library`、`/accounts`、`/mesh`、`/workspaces/:id` 改成跳到正式地址。
- **中控台右栏**：标题合成一个「需要你处理 12」，「全部已读」改成右侧灰字；卡片元信息只留「位置 · 时间」，类型交给前面的小圆点（橙色是等你，红色是失败，空心是已读），标题去掉重复的「等你批准：」这类前缀；“待回答”“需要回答”统一成“在问你”。
- **对话**：`get_history` 的 summary 结果不再贴出 `[user_message] [tool_use]` 原文，显示成 “Read N entries”，原文留在 Details 里；中控台批准卡片上方那条白色渐隐带去掉了（渐变原来用的是画布色，而中控台底色是页面灰）。
- **细节**：选中底色从亮蓝改成低饱和的蓝灰，深浅两套逻辑一致；图标栏收起时，鼠标停 300ms 就在旁边显示名字；写死的圆角全部换成令牌，深色下的下拉框也改成和浅色一样的自绘外观。
