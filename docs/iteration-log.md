## b2 · 直接能用、说法一致

对应原则 2（直接能用）、4（一致）、6（对用户负责）。界面变化主要在文字上，截图只拍有变化的地方。

- **错误说人话**（问题 8）：认不出的错误原来直接显示 stderr 第一行，比如 `Error: ENOSPC`、`ECONNRESET`。现在磁盘满、缺程序、连接被重置、没有权限都翻成一句话，中英两套词表一起改。
- **统一用词**（问题 9）：对话外面的“会话”统一叫“对话”，“审批”统一叫“批准”，待处理事项去的地方统一叫“中控台”，不再说一个没有独立页面的“收件箱”。bot 自己的收件箱和线程是另一回事，保留原名。
- **主流程去术语**（问题 10）：新建工作区里的“独立分支”改成“在副本里改：另放一份代码副本、开一个新分支，原目录不受影响”，“主仓正 checkout 着这个分支”改成“原目录正在用这个分支”；开始清单第一步从“运行时”改成“Claude Code 或 Codex”；销毁、冻结副本时说清目录、分支和没提交的改动会怎样；结束后台任务不再提 TERM。
- **派出去的活跟着派活的会话走**（问题 11）：会话用 `send_prompt` 派活又没写权限模式时，沿用自己的模式，不再让用户替别人开的会话逐条点批准；会话用 `create_workspace` 建的工作区默认挂在它所在的工作区名下，列表里折叠在父工作区下面（`standalone: true` 可以不挂）；只读的调度工具（状态、列表、记录、日志、等待）对所有会话自动放行。
- **破坏性操作**（问题 12）：冻结可以随时解冻，不加确认，只把说明写清楚。其余几处（删排队消息、删评审评论、释放认领）影响小，这批没动。

## b6 · 审阅和撤销

## b17 · 中文排版

对应第四份清单的问题 6。原则 5（细节）、0（好看）。我自己做。

- **字体**：正文的字体栈原本就是 `-apple-system` 在前、`PingFang SC` 在后，所以西文和数字用系统字体（SF），中文落到苹方，`<html lang="zh-CN">` 保证不会掉到日文字形。等宽字体栈在 JetBrains Mono、Menlo 后面补上了 `PingFang SC`，代码和终端里的中文不再随机回退。
- **中西文间距**：全局打开 `text-autospace`，WebKit 会在中文和西文、数字之间自动加四分之一字宽。实测「用nebula-web跑3次」这句宽了约 7px。文案里原来手打的空格（「近 90 天」）照旧，不会叠成两个空格。代码、输入框、终端、编辑器关掉了自动间距，保持原样。
- **行高**：新增 `--line-height-zh: 1.7`。界面里成段的中文（段落、空状态说明、设置项说明）用 1.7。对话区整体标成英文，每条消息按内容判断：至少五分之一的字母是汉字才算中文（`vocab::lang_of`，有测试），中文消息 1.7（14px 下 23.8px），英文 1.65（23.1px）。所以带一堆代码名的中文回复按中文排，夹一两个中文词的英文按英文排。
- **标点挤压**：没做成。WebKit 还不支持 `text-spacing-trim`。我在开发实例里测过苹方的 `halt` 和 `chws` 特性，「（一）。「二」，“三”：」这串的宽度一点没变。全仓库有 43 处相邻的全角标点（「」，」「）。」这类），文案本身是规范写法，不该为了渲染去改，等 WebKit 支持了再加一行 CSS。中文旁边的半角标点只扫到 1 处，在英文句子里，没问题。
