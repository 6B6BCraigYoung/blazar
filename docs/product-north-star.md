# Blazar 产品北极星

目标：做成同类里最好的软件。参考苹果做产品的**哲学**——怎么取舍，而不是它的外观。毛玻璃、圆角、SF 字体都不是重点。

## 判断标准

### 0. 好看，符合当下主流审美（最高优先级）

好看本身就是硬要求，但不能拿简单和好用去换。参照对象是当下做得最好看的同类和相邻产品：Linear、Raycast、Arc、Things、Claude 桌面版、ChatGPT 桌面版、Cursor、Notion Calendar。要学的是它们共同的审美语言：

| 要素 | 落到 Blazar |
| --- | --- |
| 排版节奏与留白 | 间距只用 4 的倍数（4 / 8 / 12 / 16 / 24 / 32 / 48），同一层级的元素间距一致 |
| 克制的字号层级 | 正文 13，辅助 12，小字 11，小标题 14，页标题 20，数字 24；字重只用 400 / 500 / 600；同一屏不超过 5 档字号 |
| 中性色加一个强调色 | 表面色是 4 级灰阶（画布、侧栏、浮起、控件）；蓝色只用于主按钮、选中和焦点；状态色只给小圆点，不涂大面积 |
| 深浅色都精调 | 两套主题各自调过对比度和层次，不是一套反转；浅色侧栏接近白色，不发灰发脏 |
| 细线、柔和阴影、统一圆角 | 分隔靠 1px 细线或底色差，二者不叠加；阴影只有三级（无、浮起、浮层）；圆角只有三档（控件 6、卡片 10、浮层 14）加胶囊 |
| 图标统一 | 一套线性图标，同一线宽、同一尺寸档（14 / 16） |
| 动效短而有弹性 | 120–200ms，进入用略带回弹的缓动；不做常驻动画 |
| 密度适中 | 列表行高 32–36，卡片内边距 12–16；不为“透气”牺牲一屏信息量 |

性能约束：不做大面积模糊；阴影不叠三层以上；不新增常驻动画；主滚动区保持单一分块图层（见 `bc67330`）。

### 1. 少即是多

每个界面只做一件主要的事。能删的按钮、设置、提示都删掉，默认值要好到大多数人不用改。
在 Blazar 里：中控台只回答“谁在等我”；工作区页只服务“跟这个智能体把活干完”；设置只放真正因人而异的东西。

### 2. 它应该直接能用

用户不用懂端口、令牌、会话 id、分支、worktree、hub、EasyTier 这些内部概念。出错时说清楚发生了什么、下一步按哪里；能自动恢复的就别打扰。
在 Blazar 里：断网续跑、额度用完自动换号、远端缺 CLI 自动装，这些已经做到；没做到的是错误原文直出、首次打开先问“运行时”、新建工作区要懂分支。

### 3. 内容优先，界面退后

对话、代码、结果是主角。边框、标签、状态条都要安静：能用留白分组就不用框，能用灰度区分就不用颜色。

### 4. 一致

同一件事在每个地方的叫法、样子、位置都一样，同一种操作只有一种主要做法。
统一用词：工作区、对话、智能体、机器、中控台、任务、自动化、后台任务、批准、额度（详见问题 9）。

### 5. 细节里见品质

动效节奏、空状态、加载、错误、键盘操作、深浅色都是产品本身，不算收尾工作。

### 6. 对用户负责

隐私、数据不丢、操作能撤销、有风险的动作写清后果。能撤销的不弹确认，不能撤销的用一句人话讲清楚后果。

### 7. 整体体验

安装 → 首次打开 → 加机器 → 建工作区 → 对话 → 审批和卡片 → 中控台 → 多机器、多账号 → 升级，是一条完整的路。

### 同类对比

做得比我们好的地方：
- **Conductor**：⌘⇧N 一键新建工作区，setup 脚本加端口变量，建好就能跑；从 issue、PR、分支起步。
- **Claude Code 桌面版**：权限只有一套 5 档词汇，⌘⇧M 切换；`/rewind` 能分别还原代码和对话，并写明哪些还原不了；后台自动更新，分 stable 和 latest 两个渠道；只在“完成且你没在看”时才通知。
- **Codex**：复用 `~/.ssh/config`；Handoff 能把对话连同 git 状态迁到另一台机器；手机扫码后可以在手机上审批。
- **Cursor**：一个 Agents 窗口管本地、worktree、云端、SSH 上的所有智能体；首次使用强制设花费上限。
- **Linear、Raycast**：同一屏只有 4–5 档字号；分隔几乎全靠留白和底色差；只有一个强调色。
- **Warp、multica**：通知只分“请求”和“错误”两类；只在需要决定时才提醒。

我们更强的地方：跨机器的统一中控台（按“谁在等你”排序，带决定卡）；多账号额度自动分摊；不绑定运行时，自带组网；bot、后台任务和自动化能放在用户自己的 GPU 机器上跑。这些优势要靠减法才能显出来：默认只露出中控台、新建工作区、改动审阅三样，多机和多账号做成自动生效、只在需要时出现。

## 顺序与分批

排序原则：对体验提升最大、风险最小的先做。视觉打底的改动放第一批，因为后面每一批都踩在它上面。

**第一批：视觉打底（问题 1、2、5、7、3、4、6）**
令牌收敛 → 控件扁平化 → 表面色重调 → 状态色收敛 → 中控台 → 对话页 → 工作区列表和空状态。几乎只改 CSS，逻辑不动，风险最低，观感提升最大。

**第二批：直接能用、说法一致（问题 8、9、10、11、12）**
错误不直出 → 统一用词 → 主流程去掉术语 → 派生会话继承权限并挂在父工作区下 → 破坏性操作补撤销和后果说明。

**第三批：减法与完整的路（问题 13、14、15）**
设置减半 → 入口收敛 → 应用内升级和版本不一致提示（公证另请用户决定）。

## 工作方式

- 一批一个分支（`ns/b1`、`ns/b2`……），做完合并 main。
- 验证就是编译、CI 那套检查和改前改后对比截图（深浅色各一张）；截图只用开发实例的演示数据。
- 每批在 [iteration-log](iteration-log.md) 追加一节：改了什么、对应哪条原则、截图路径、提交号。截图存在 `docs/iteration-shots/<批次>/`。
- 界面文字：对话里面用英文（照 CLI 原文），对话外面用中文。
- 不为好看牺牲性能：不加大面积模糊、复杂阴影、常驻动画，也不给页面单独加图层。改前改后各跑一次 `scripts/perf`。
